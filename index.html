代理方式

      
把客户端（或主路由 DHCP 下发）的网关和 DNS 指向本机即可全局透明代理
        

      

      
TUN 选项

        
协议栈
默认：sing-box 1.15+ 用自有协议栈（推荐，最快最省），旧 sing-box 由内核自选；mihomo 用 system（v9.2.5 起，以前是 mixed）

          

        
多队列 multi_queue
sing-box 1.15+ 自有协议栈的多队列 TUN（IFF_MULTI_QUEUE），吞吐随 CPU 核心数增加；只在 Linux、多核、协议栈为「默认」时生效，默认关闭

        
网卡名称

        
auto-redirect
用 nftables 重定向 TCP，旁路由性能更好；内核不支持时自动关闭

        
strict-route
严格路由，防止流量绕过 TUN；可能影响局域网访问，默认关闭

        
TUN MTU
TUN 网卡的最大传输单元，默认 9000；个别网络 MTU 小时可降到 1280–9000

        
QUIC 屏蔽
拦截走代理的 QUIC（UDP 443），浏览器自动退回 TCP；节点 UDP 转发差时 YouTube 等反而更稳。直连的站点不受影响，默认开启

        
MSS 钳制
把转发 TCP 的 MSS 钳到路径 MTU（clamp-mss-to-pmtu），MTU 不对称的链路不再丢大包；只在 TProxy / TUN 时生效，默认关闭

        
auto-route、auto-detect-interface 已开启，DNS 劫持 any:53

      
IPv6 透明代理
核心与 DNS 启用 IPv6，并代理 IPv6 流量；需客户端以本机作为 IPv6 网关

      
故障自动直连（看门狗）
核心挂掉时自动重启，仍失败则关闭透明代理保证局域网能上网

绕过设备（不走代理）

      
每行一个 IP、网段或 MAC（如 192.168.1.50、2408:xxxx::/64、AA:BB:CC:DD:EE:FF）。TUN 模式下按 IP / 网段生成直连规则（MAC 仅 TProxy 有效）。被绕过的设备请把 DNS 设为主路由。

      

    
直连不进内核（入口旁路）

      
TProxy 模式下，目标是直连地址的连接在 nftables 入口直接放行，不再经过内核转发：直连更快、更省 CPU。默认关闭（所有流量照旧进内核）。放行的连接在「连接」页和流量统计里看不到。TUN 模式下不生效。

面板更新

      
从 GitHub 仓库 https://github.com/Skycnhe/Shunt-release（分支 shunt）获取最新面板文件：先经 mihomo 代理下载，失败再直连；国内可填加速地址。更新前自动校验并备份，可一键回滚。预览版通道取同仓库的「-preview」分支（最新测试提交，版本号形如 v8.10.30-preview.N+提交号），切回正式版后点「立即更新」即装回正式版。

      

      

      
查内核 / 面板版本要用 GitHub API，未登录每个 IP 每小时只有 60 次，机场出口常被别人用完（HTTP 403 rate limit）。填一个不勾任何权限的 Token（GitHub → Settings → Developer settings → Personal access tokens）可提高到每小时 5000 次；只发给 api.github.com，不进备份。限流时面板也会改从 GitHub 发布页取版本号
